# 本机公共数据目录

这是需要配套节点启用的新项目模式。旧项目和旧任务不自动改变路径或工作区行为。

## 使用

```sh
gpuctl use MACHINE_ID
gpuctl data roots --json
gpuctl project create experiment --storage local-roots --workspace-mode project
gpuctl push .
gpuctl ssh
```

容器自动只读挂载本机 `/data`，有可用加速目录时还挂载 `/fast-data`。代码按路径读取，例如 `/data/imagenet-1k/train`，不用添加 `--data` 或等待 SSD 缓存。多个容器共用原文件，挂载不复制数据。

`project` 工作区模式让开发和训练共用该项目的可写代码目录；修改会影响其他使用它的任务。`task` 模式从本次代码版本建立每任务独立的可写目录，恢复原任务继续使用该目录；只复制项目代码，不复制公共数据。两种模式都保留独立的 `/outputs`。环境仍需按现有流程发布，训练继续固定已发布环境版本。

```sh
gpuctl project publish
gpuctl run --machine MACHINE_ID -g 1 -- python train.py --data /data/imagenet-1k/train --output /outputs
```

网页新建项目处，在节点确认支持后显示“本机公共目录（只读）”及工作区模式，和 CLI 使用同一接口。

各机器的数据内容可以不同；默认明确选择机器。AUTO 只会使用已有兼容项目版本的候选，不自动跨机复制本模式项目，也不能推断训练代码需要哪个目录。数据跨机准备仍是单独操作，完成后再提交训练。

## 管理员配置

在新节点发布配置中添加以下可选配置；未配置时保持原行为。目录和挂载点是示例，须填写该节点已核对的本地数据盘。不要在运行中的固定版本目录里直接覆盖代码或配置。

```json
{
  "publicDataRoots": {
    "enabled": true,
    "roots": {
      "data": {"path": "/srv/data-volume/public-data", "mountPoint": "/srv/data-volume"},
      "fast": {"path": "/srv/fast-volume/public-data", "mountPoint": "/srv/fast-volume"}
    }
  }
}
```

`fast` 可省略。配置目录必须预先存在，位于确认挂载的本地文件系统中。导出目录必须与平台控制目录、旧数据仓库根及私人数据区分开；不允许把包含上传票据和私人工作区的旧仓库根整体导出。

新项目保存目录身份与模式。配置改变或原目录被替换不会让旧项目悄悄改读新路径；应显式迁移项目。必需根不可用时拒绝启动；可选根不可用会明确提示，不回落到系统盘同名目录。

运行器在容器整个存活期间持有公共根的共享锁。维护公共数据时必须使用相同的独占锁，并持有到删除结束；本版本不提供自动公共数据淘汰。仅把公开目录 chmod 为只读不能替代容器只读挂载或使用关系检查。

节点安装清单包含 `public-data-roots.py`，两种运行器与个人容器均需配套更新。终端启动检查只需要会话元数据空间；上传、发布、复制、环境展开及训练原有写入检查仍保留。

## 本次实现与后续范围

已实现本机公共根挂载、创建时固定模式、项目共享/任务隔离工作区、网页/CLI 入口、根级使用锁及终端小额空间检查。工作区和输出仍使用节点当前配置的项目卷，不自动迁往其他磁盘。

独立私人目录清理、直接上传/跨机复制到公共根、可选路径依赖筛选及工作区跨卷选址需要后续配套；现有传输不会因启用此模式换编号、位置或重新上传。本文件不宣称这些后续功能已上线。
