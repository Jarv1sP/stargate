## 检查点 1：读取契约与用例

Git 回退点：`1444051`。

- 新实现位于 `src/`，不导入旧 `PortalService`、演示服务或 `installX`。
- `/api/v2/data/read-location` 明确区分 `directory`、`warehouse`、`cache`，不接受宿主路径或调用者自报用户身份。
- `ResolveDataRead` 只依赖 `access.requireRead` 和 `sources.inspect`，没有复制、准备、容量检查或调度依赖。
- 解析得到的是读取位置观察，不是已挂载证明、训练准入或数据租约。
- 五项契约／用例测试通过：三种来源、无隐式回退、无复制依赖、拒绝时零 I/O、异步期间撤销权限和私有字段不外泄。

## 检查点 2：真实目录、HTTP 与共用 SDK

- 同一个 `DataClient` 和 `JsonHttpTransport` 已在真实 Chromium 和 Node 运行，Cookie／令牌调用同一个 HTTP 接口；认证和来源权限仍是显式端口，未接生产身份库。
- 16 项 V2 测试通过，另有真实浏览器对照通过。覆盖 100 个并发读者共用原 inode、源文件不变、缓存缺失不阻断原目录／仓库、拒绝时零目录查询、来源回包不匹配、报文上限及错误不泄露宿主路径。
- 首轮真实浏览器发现 `fetch` 被当作对象方法调用造成非法接收者；已改为独立函数调用，重新验证通过。
- 新链路不导入旧服务，未替换生产或现役灰度的状态所有者；没有提交 GPU 任务。

## 检查点 3：共用客户端会话生命周期

Git 回退点：`2bde55e`。

- `ClientSession` 独占凭据快照和请求生命周期；HTTP 层不保存第二份凭据。身份改变时关闭旧请求上下文，新调用只使用新凭据。
- 返回 HTTP 响应后、解析正文后都确认会话仍有效；即使传输实现忽略取消信号，也不交付旧账号的迟到结果或错误。
- 单个请求取消和退出登录上下文是不同动作；取消查询不会注销会话，也不会重放调用。
- 20 项 V2 测试通过，真实浏览器验证同一 SDK 的 Cookie／令牌调用、关闭后零请求、重新打开及源文件不变。
- 这不是完整登录系统：服务器会话签发／撤销、令牌持久化和真实授权适配器仍待实现；未改变生产登录或现役灰度。

## 检查点 4：服务端身份与数据权限读取

- 会话验证、数据权限规则、SQLite 查询和 HTTP 凭据解析分开；规则只依赖明确事实，不依赖旧 Portal 或演示服务。
- 会话撤销、过期、账号停用及授权修订号不一致统一拒绝。机器权限与数据权限独立；管理员可访问已启用机器，但不能绕过私有数据授权。
- 仓库／缓存位置共用同一个固定版本的权限资源；同名原目录按机器隔离。缓存不存在不影响已有原目录和仓库的可读性。
- SQLite 查询适配器不创建表、不写数据；初始 schema 显式执行，不是隐式迁移，也不回滚调用者已有事务。持久库以只读方式重开验证通过。
- 本地文件系统适配器固定节点 ID，拒绝把本机路径当作其他机器的读取证明；普通组装函数接收来源适配器，VPS 后续接远端适配器，不硬连本机文件系统。
- 29 项 V2 测试和真实浏览器 SDK 回归通过。首轮架构检查误禁同层模块引用，已修正，同层组合允许、向外层依赖仍禁止。
- 所有 schema 和权限变更仅发生于临时测试库，没有迁移生产账号、数据库或数据目录。会话签发／滑动续期与生产授权接入仍未完成。

## 检查点 5：登录和持久会话核心

- `Login` 仅协调账号读取、密码验证、失败记录、令牌生成和会话签发；`SessionLifecycle` 处理续期／注销。SQL、密码算法、HTTP 均不混入用例。
- 保持 PBKDF2 SHA256 密码算法与旧迭代数兼容，数据库只保存会话令牌摘要；30 天空闲过期、每小时续期规则集中定义。生产凭据导入未实现，不表示现役数据库可直接替换。
- 密码校验后在签发事务中复查账号和凭据修订号；失败写入整笔回滚，不返回虚假成功。注销只作用于本人指定会话，失效会话不能通过续期复活。
- 密码并发限制由单个权威进程的 `Login` 实例承担；不是多进程分布式限流。账号／密码修改必须递增相应修订号，这些写入用例尚待实现。
- 37 项 V2 测试通过，无跳过；真实浏览器共享读取 SDK 回归通过。新增测试覆盖旧密码格式、数据库重开、失败限制、并发、校验期间账号变化、写入故障回滚、会话上限和注销／续期。
- 本次不是完整登录交付：尚无新登录 HTTP 路由、客户端凭据持久化或生产迁移。浏览器测试仍覆盖读取链路，不冒称已验证新登录端到端。没有更新线上服务，也未运行旧系统全量 Node／Python／浏览器验收。

## 检查点 6：统一登录 HTTP／SDK

- 网页和 CLI 共用 `SessionClient`、会话契约和登录／续期／注销用例；区别仅是 Cookie 或令牌交付。错误与有界 JSON 读取也集中实现，没有复制第二份 API 规则。
- 浏览器令牌只由 HttpOnly、SameSite=Strict Cookie 承载，HTTPS 加 Secure；Cookie 登录必须同源。CLI 使用 Bearer，显式错误 Bearer 不回退 Cookie。两者都不接受自报账号 ID／角色。
- 登录期间关闭原客户端业务请求，确认新身份后才重新打开。失败登录不会继续使用旧 Cookie 身份；异步迟到结果不能覆盖客户端的新会话。这里指当前 SDK 生命周期，不表示失败登录会删除浏览器旧 Cookie 或撤销其他会话。
- 注销响应丢失仍报结果未确认并关闭当前本地会话，不假称服务端已撤销，不自动重发。独立网页／CLI 会话各自注销。
- 47 项 V2 测试、原读取浏览器回归和新增真实 Chromium 登录回归通过，无跳过。浏览器测试使用真实 PBKDF2、SQLite、HTTP 和同一 SDK，验证持久 Cookie 重建浏览器上下文、受保护目录读取、HttpOnly、注销及 CLI 会话独立。
- 登录不再依赖数据读取模块：会话读取与有效性规则归身份模块，数据权限组合这些事实。组装不建表、不监听端口、不读生产配置。
- 尚未接入生产／现役灰度，未迁移账号、未保存 CLI 令牌文件；客户端自动续期策略、恢复时查询当前身份以及账号写入待接。未跑旧系统全量 Node／Python／UI 验收，不将本段通过称为整站可替换。

## 检查点 7：真实身份恢复

- 新增统一的 `/api/v2/session/current` 与 `SessionClient.restore`。网页沿用 HttpOnly Cookie，CLI 由平台适配器传入已保存的候选令牌；不信任本地缓存的姓名／角色。
- 服务端按当前会话、账号和授权修订返回账号资料及到期时间。该查询不新建会话、不续期、不返回凭据；刷新到期时间仍使用明确的 refresh 操作。
- SDK 在恢复完成前关闭业务请求；无效会话、网络失败和损坏回包分别报错，均不会把客户端误置为已登录。迟到恢复不能覆盖外部切换的新会话。
- 53 项 V2 测试和两组真实浏览器回归通过，无跳过；浏览器持久 Cookie 重开后通过 current 接口确认身份，再读取受保护目录。测试包含最新显示名、无隐藏写入、撤销／过期／停用／授权变化和恢复并发。
- 未部署、未改生产数据；CLI 凭据文件读写、主动续期策略和账号管理尚未实现。未执行旧系统整站验收，整体重构仍未完成。

## 检查点 8：CLI 私有凭据与真实进程恢复

- 令牌持久化通过共享 `SessionClient` 的同步存储端口接入；网页 Cookie 不接这个端口。平台文件／SQLite 实现在基础设施层，SDK 无文件系统依赖。
- 显式创建 0600 本地客户端凭据库，与服务端数据库分离，按 API origin 保存令牌，不保存密码、角色或账号资料。SQLite 单语句写入和条件删除处理多进程竞争，不另造文件锁协议。
- 旧进程只删除自己使用的令牌，不覆盖另一进程较新的登录；断网和丢注销回执保留恢复凭据，明确失效才清除。保存失败返回独立错误，不宣称持久登录成功；已签发的服务端会话及内存身份不因此假装回滚。
- 新增显式开发入口 `node scripts/v2-client.mjs --help`，支持 login/current/read/logout；必须指定候选 API origin 和本地凭据文件，不默认连接线上、不修改已安装的 gpuctl。密码仅从 stdin 读取，不放参数或输出。
- current/read 每次启动先恢复真实身份，再调用续期接口；服务端仍按小时更新到期时间。身份查询本身保持只读。
- 62 项 V2 测试、两组真实浏览器回归通过，无跳过。新增真实 CLI 子进程登录→退出→重启读取→注销，以及独立进程写入后旧令牌清理的验证。
- 当前文件权限适配器只在 Linux/POSIX 验证；Windows 原生 ACL 与发行打包尚未完成，不宣称跨平台上线。未部署或迁移生产，未执行旧系统整站验收。

## 检查点 9：账号角色与启停

- 独立账号策略、查询／修改用例、SQLite 仓储、HTTP 与共享 `AccountClient`。管理员身份来自实际会话，不信任请求里的 actor／角色。
- 写入事务内同时核对管理员会话、目标修订号和其他启用管理员数量。保留现役最后一名管理员及禁止修改自身角色／停用自身的规则；无变化的 enabled 请求不使会话失效。
- 角色／启停变更递增账号授权修订，旧会话立即拒绝，重新启用也不会复活旧会话。同一版本并发修改只允许一笔成功，存储故障整笔回滚。
- 查询接口返回当前角色、启用状态和修订号，供修改前读取及丢回执后核对。查询是当前状态观察，不冒充原操作回执；SDK 不自动重发写入。
- 70 项 V2 测试、两组真实浏览器回归通过，无跳过；覆盖跨账号拒绝、自身／最后管理员保护、停用后重登、过期修订、事务故障和丢回执。真实浏览器 Cookie 与 Node Bearer 使用同一账号 SDK，对同一目标验证修改与版本冲突。
- 没有修改真实用户权限或部署线上。账号创建、密码重置、机器／数据授权写入、账号列表与前端页面仍未完成；未执行旧系统整站验收。

## 检查点 10：密码重置

- `ResetPassword` 在计算密码前验证管理员及目标版本，异步 PBKDF2 结束后在事务内再次核对；权限变化或其他账号修改不会被迟到的密码结果覆盖。
- 新密码摘要、凭据修订和账号授权修订在同一事务提交。旧密码与所有旧会话失效；写入失败不留“密码已变、会话未失效”的半状态。
- 保留现役 8–128 字符要求和管理员自重置能力；自重置会使发起者当前会话同样失效。请求密码不裁剪，接口不返回密码或摘要。
- 共用契约、HTTP 和 `AccountClient.resetPassword`；不添加自动重发或隐藏兼容路径。丢回执时密码结果仍属未确认，查询账号修订不是原操作回执。
- 75 项 V2 测试和两组真实浏览器回归通过，无跳过。覆盖普通用户零密码计算、计算期间停用／版本变化、事务故障回滚、多会话失效与自重置；真实浏览器重置后 Node SDK 用新密码登录成功。
- 未改真实密码、未部署。账号创建、账号列表、机器／数据授权写入及管理页面仍待实现；未执行旧系统整站验收。

## 检查点 11：账号创建

- `CreateAccount` 在密码计算前验证管理员，事务落库前再次核对。账号与密码摘要原子提交，凭据插入失败不留下无法登录的半账号。
- 保留现役中文／小写用户名、显示名、密码长度规则和 admin 保留名。新账号无机器／数据授权记录；管理员角色的既有访问规则不因此改变。
- 调用方在提交前生成并保留新账号 UUID，SDK 不换号重试。重复 ID、重复用户名分别拒绝，原 ID 可用于丢回执后的当前状态查询；该查询不是原创建操作的回执。
- 81 项 V2 测试、两组真实浏览器回归通过，无跳过。覆盖并发同名创建、非管理员零密码计算、计算期间撤权、事务故障、创建后登录及未隐式授权；浏览器通过同一 SDK 创建后，Node 登录取得相同账号及中文显示名。
- 只写临时测试账号，没有修改真实账号或部署。账号列表、机器／数据授权写入、管理页面和生产迁移仍待完成；未执行旧系统整站验收。

## 检查点 12：账号列表与 CLI 查询

- 管理员列表返回姓名、用户名、角色、启用状态及修改所需版本，不返回密码、摘要或令牌。网页／CLI 共用 `AccountClient.list`，新增独立 V2 CLI 的 `accounts --limit N --after ID` 命令。
- 单条 SQLite 查询观察管理员会话和当前页，不获取写锁；每页最多 100 条，按账号 ID 游标分页。分页是逐页当前观察，不承诺跨页冻结快照；新插入在游标之前的账号需重新从首页查看。
- 普通成员不能枚举账号；管理员在翻页期间被停用、撤销或变更授权后，后续请求不继续返回旧权限下的数据。
- 账号 HTTP 层整理成显式路由／契约／用例映射，共享身份解析与错误处理，不增加任意方法调用入口。

## 检查点 13：机器授权与用卡额度

- 独立计算资源策略模块保存单机上限与跨机总上限，保留现役总额度不大于单机上限合计、管理员不配置成员额度的规则。数据权限不混入计算资源策略。

## 检查点 71：固定受管操作适配与未知结果区分
